# FikaAI — 90-second demo script

**Team Auras · Kenya · Online**

---

**0–10s — Problem**  
Imagine needing a specialist in Nairobi, but not knowing whether the facility can actually help you before you make the trip. For many people, healthcare access isn't only about finding care — it's about having the right information when connectivity isn't reliable.

**10–25s — Product / AI**  
FikaAI uses AI to understand a patient's natural-language request and turn it into structured healthcare-search intent.

*(On screen: enter “I need a cardiologist in Nairobi.”)*

**25–40s — Provider discovery**  
The AI doesn't invent healthcare providers or availability. It helps interpret the request, while provider information comes from the application's provider records.

**40–52s — Journey**  
The patient can select a facility and save the next steps as a healthcare journey.

**52–68s — Offline (key moment)**  
Now we remove the internet connection. The saved journey is still available, so the patient can continue with the information already stored on the device.

**68–80s — Sync**  
When connectivity returns, FikaAI can synchronize pending journey actions and refresh information.

**80–90s — Close**  
This prototype demonstrates a simple idea: healthcare navigation should not completely stop when connectivity does. Next, FikaAI can connect this foundation to verified provider networks, broader healthcare channels, and real-world availability data.

FikaAI — healthcare access that works when connectivity doesn't.  
Team Auras, Kenya.
